## App

What a TD already has: Setup catalogs, a per-tournament workspace
(roster, assignments, day-of, payroll, reports), a review inbox that a
person files, Get mails for Gmail and Outlook, an inbox-people list with
Add to Players, and an idle **Still there?** prompt (warn two minutes
before a 15-minute logout). Help (`?`) already describes those surfaces.
Trash restores tournaments and incidents. Clear inbox hides CourtOps
copies and does not delete provider mail.

Checked against the code, that behavior holds:

- Idle constants are `IDLE_MS = 15 min` and `WARN_BEFORE_MS = 2 min`.
- All 43 routers are mounted: `health`, `auth`, `me`, and `ingest` are
  open; the other 39 require an admin session, including `inbox_people`,
  `gmail_feed`, `outlook_feed`, `inbox_feeds`, and `td_chat`.
- Trash queries only `tournament` and `tournament_incident`. Inbox Clear
  sets `email_message.deleted_at`.

The architecture doc said emails are not soft-deleted and that Trash is
the only `deleted_at`. That sentence contradicted Clear inbox. The doc
now describes both columns. The code was left as shipped.

No TD-facing break turned up that this pass should change. End-to-end
findings F1–F4 are already documented (free-mile band, row-vs-player
merge counts, unmatched mail, Windows `httpx`). They are not open bugs.

### Deferred

These were already out of scope. This pass does not build them.

1. **Google Maps driving-distance key.** Distance Matrix is scaffolded
   behind `GOOGLE_MAPS_API_KEY`; great-circle remains the key-free
   path. `GEOCODER=google` address lookup is still unimplemented on
   purpose. Needs a billed key, egress, and a cost decision.
2. **Mail-provider wiring.** `POST /api/ingest/email` and the Fly token
   exist. A Mailgun / SendGrid / worker account is external.
3. **LLM-triage privacy decision.** Off-box reading of minors' email
   stays blocked until that decision. The on-box leftover pass is
   already shipped and was only documented here.
4. **Prod PII / DB-role deploy work.** Least-priv role, app TLS, disk
   encryption, secret manager, retention cron. Needs the deploy target.
   Column encryption is already in the app.
5. **DB connection pooling (D13).** One connection per request until
   multi-worker load shows up.
6. **Process-local login throttle (D14).** The in-process dict is
   enough for one instance. Multi-instance needs a shared store.
7. **CSRF tokens (D18).** Session cookie is `HttpOnly` and
   `SameSite=Strict`; the SPA is same-origin. Tokens wait on a
   cross-site client.
8. **Per-site coordinator role.** Improvement-plan P4, parked with
   multi-user scope. Admins and officials are the roles that ship.
9. **Configurable mileage and cert catalogs.** Pay uses the shipped
   constants (`FREE_MILES=50`, `MILEAGE_RATE=0.65`, `MILEAGE_CAP=100`)
   and the certification-rate table. A TD-editable formula catalog is
   new product scope.
